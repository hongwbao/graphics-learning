## 概念与必要数学

### 一个采样位置，可以收到多个候选

设A/B两个不透明表面都覆盖某个像素中心。片段着色器可以给两者都算出颜色，但最终通常只想看最近的一个。深度缓冲为每个位置保存当前胜出者的深度；开启LESS时，新深度更小才替换它。

本课使用默认窗口深度[0,1]，每帧清除为1，并启用深度写入。不同表面的深度可区分时，改变不透明物体的提交顺序不应改变遮挡。若量化后相等，严格LESS会保留先写入者。透明混合的顺序是另一类问题，不能据此推断。

### 透视深度，不是“距离除以far”

设前向距离d=−z_view>0，近远面为n、f，满足0<n<f。OpenGL透视投影、透视除法与默认深度范围映射合起来，窗口深度为：

z(d) = f/(f−n) − fn/[(f−n)d]

z(n)=0，z(f)=1

z是深度缓冲使用的量，d是观察空间里的正距离。公式中的1/d意味着精度向近处集中。把near设得极小，会让远处的深度差被压缩；不是单纯“far越大就按同一比例损失所有地方的精度”。

### 连续深度，最终还要放进有限表示

q = round(z · (2ᵇ−1))

Δd ≈ [(f−n)d²] / [fn(2ᵇ−1)]

b是本实验的定点深度位数，q是整数格编号。Δd是局部一格对应的近似距离分辨率，来自对z(d)求导后取倒数；它随d²增长。两个不同的d可能落入同一q。真正的GPU还涉及具体深度格式、舍入、插值与浮点误差，本图只隔离这一种机制。

左图使用未量化的理论距离决定可见性，右图使用q和LESS。两张图不一致的格子，是这组几何与量化设置下的可见性误差，不是随机制造的噪声。

### 排查与修复，不要只调一个神秘偏移

先检查深度测试是否启用、比较函数是否正确、是否清除并允许深度写入，再验证near/far与表面的真实距离。如果确有共面重复几何，删除冗余表面常比硬加偏移更直接；需要贴花时可研究偏移方案，但它也可能导致悬浮或遮挡错误。

把near推远会改善标准透视定点深度的远处精度，但会裁掉更近内容；提高位深不是免费改变设备格式的滑块。本实验的b是教学参数，并未修改浏览器GPU深度缓冲。Reversed-Z与浮点深度是后续延伸，不能把此定点公式直接当成所有实现的结论。

延伸：为什么只交换顺序不是最终修复？

当两层落入同一量化深度格，交换顺序只改变谁在相等时先写入。它可以支持“深度无法区分”的假设，却不能恢复正确的几何距离信息。

## 交互实验：理想遮挡与量化遮挡，同时比较

两张近共面斜面都覆盖网格。左边按真实距离选最近表面，右边先量化深度再执行LESS。青色A、砖红B，黄色边框标出同一深度格；改变提交顺序查看平局如何被打破。

可调参数：

- `near`：近面 n，默认 0.1。
- `far`：远面 f，默认 500。
- `distance`：表面中心距离 d，默认 60。
- `separation`：B的距离偏移 Δ，默认 0.012。
- `slope`：两表面的微小斜率，默认 0.04。
- `bits`：教学定点位数 b，默认 16。
- `order`：提交顺序，默认 ab。

预设对照：低精度，暴露提交顺序；推远near对照；完全共面：没有唯一前后；观察近处。

### 亲手修改核心代码

depth把观察距离映射为窗口深度；quantize把它落到定点格；choose才执行可见性比较。把LESS的“<”改成“<=”，先预测深度相等时由谁获胜。不要把位数参数解释成浏览器真实GPU格式。

```js
const n=input.near,f=input.far,levels=2**input.bits-1;
const depth=d=>f/(f-n)-f*n/((f-n)*d);
const quantize=d=>(d<n||d>f)?null:Math.round(depth(d)*levels);
const choose=(a,b,quantized)=>{
  let winner=0,best=quantized?levels:1;
  for(const id of input.order==='ab'?[1,2]:[2,1]){
    const d=id===1?a:b,z=quantized?quantize(d):(d<n||d>f?null:depth(d));
    if(z!==null&&z<best){best=z;winner=id;} // 严格LESS：平局不替换
  }return winner;
};
return renderPlanes(choose,depth,quantize,n,f,levels);
```

框架把脚手架与上面的核心函数体合并后放进 Worker 执行；返回的数据驱动画布。编辑成功代码后控件沿用新版本，错误/超时保留上次图像。可下载包含脚手架的完整核心实验代码。

### 应该观察到什么

先区分真实几何距离、投影深度和存储量化。平局及顺序敏感可支持精度假设，但不是所有遮挡错误都来自z-fighting。

### 简化与不能推出的结论

CPU模拟标准透视深度的定点四舍五入和LESS，微斜面是按屏幕格定义的教学表面；不是实际GPU深度读回，也未包含浮点深度、MSAA、硬件插值误差或Reversed-Z。

## 预测、实验、解释任务

### 近处与远处，谁更容易落同一格？

保持near、far、b和两面偏移不变，比较d=3与d=60。先用Δd近似式预测精度比例，再检查量化平局数量。

需要时再看提示：近似分辨率随d²增长，但某一对值是否撞格还取决于格边界。

### 只交换顺序，为什么不能证明修复？

运行低精度预设，交换A/B提交顺序。解释变化来自LESS平局而非几何真的改变。再用推远near或提高教学位深作对照。

需要时再看提示：两层量化值相同，先写入的候选留下；顺序并没有补回丢失的深度信息。

### 写出有代价的修复建议

假设需要同时渲染0.05米近物和1000米道路，讨论推远near、分层渲染、去除重复几何、深度偏移分别会牺牲什么。区分本实验支持的结论与需要真实GPU测量的结论。

## 常见误区

- 以为深度缓冲保存的是线性米数：核对投影与范围映射。
- 把交换顺序当作最终修复：它不能恢复丢失的精度。
- 把教学b滑块或斑纹图当成GPU实测：本实验明确只演示量化机制。
