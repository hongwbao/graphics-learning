场景里有什么？

必须掌握 · 15 分钟

想象你给一个灰色立方体拍照。相机往右挪，物体在照片中向左；灯挪到另一边，亮面改变。几何形状没有变，图像却不同。一张图不只由模型决定。

模型：有什么

顶点给出位置，三角形把点连成表面。本实验的立方体有 8 个几何角点、6 个面、12 个三角形；为每个面保留独立法线，代码展开成 36 条顶点记录。

相机：从哪里看

相机用位置和朝向定义观察坐标，再用投影定义视野。它不必是可见物体。你在重建中估计的相机外参，与渲染中的观察变换紧密相关，但要先核对坐标约定。

光源与材质：怎样显色

材质描述表面的响应；光源提供照明。本实验把两者作为参数交给片段着色器。OpenGL 不会自动为场景加灯，你需要在代码中写出计算规则。

着色器与绘制：怎样处理

顶点着色器处理提交的顶点，输出裁剪空间位置及其他属性；片段着色器计算候选片段的颜色。CPU 负责准备数据、更新参数并发起绘制，GPU 执行大量并行计算。

与 3D 重建连起来

重建得到网格，并不自动得到原始照片。相机、材质、光照、可见性和采样都会影响重投影图像。因此图像误差既可能来自几何，也可能来自成像设置。图形学更广，还包括建模、动画等；本课程先聚焦图像生成与实时渲染。

从这三处开始，改前先给出预测
  1. ambient = 0.0：背光面会怎样？再改为 0.5 比较。保持 diffuse 不变时，正面也会变亮，亮度和可能超过 1。
  2. diffuse = 0.0：再转动灯，亮暗还会变化吗？
  3. 用 vec4(n * 0.5 + 0.5, 1.0) 替换输出颜色：这时改的是几何，还是方向的可视化？
变量：n 为单位法线，l 为指向光源来向的单位方向，uColor 为基础色；ambient 是常量底光，diffuse 是方向光权重，brightness 是最终亮度系数。它们是可编辑代码中的变量。RGB 输出超出 [0,1] 会在本例默认颜色缓冲中被截断，因此变得更亮不一定能看出更多差别。


延伸：默认亮度公式里的符号是什么？
下面解释课程默认代码；自定义后以编辑器的表达式为准。b = 0.22 + 0.78 × max(n · l, 0)。b 是亮度系数；n 是表面向外的单位法线；l 是从表面指向方向光来向的单位方向。点积 n · l 衡量两者对齐程度：正对时为 1，垂直时为 0，背光时为负；max 与 0 取较大值，避免负亮度。0.22 是人为保留的常量底光，0.78 控制方向光贡献。最后把 RGB 三个分量分别乘以 b。它只用于建立直觉，不是完整物理光照模型。改大 0.22，会抬亮背光面、减弱明暗反差；请先预测再改代码。
本实验简化了什么？
使用 WebGL 1 / GLSL ES 1.00，沿用你熟悉的 OpenGL 管线思想；没有引入 Three.js。只有两个立方体和地面，固定 50° 透视视场角；相机只做横移和沿 Z 方向移动，始终保持固定俯视朝向。光是无距离衰减的方向光，采用简单漫反射加常量底光，没有投射阴影、纹理、PBR 或完整线性颜色管理。线框额外用 LINES 绘制三角形边，不是 GPU 光栅化内部状态的直接截图。后续周次会逐步拆开这些细节。

本周只需读懂这一行
pclip = P · V · M · plocal
本课程使用列向量，从右向左应用变换。plocal = (x, y, z, 1)T 表示模型自己的坐标；M 把它放进世界，V 换成相机视角，P 负责透视投影；pclip 是四维裁剪坐标，还不是屏幕坐标。字母都代表变换规则，本周无需背下矩阵元素。
为什么相机往右，物体看起来往左？
先去掉旋转，只看平行于世界 X 轴的相机横移：
xview = xworld − cx
xworld 是点的世界横坐标，cx 是相机横坐标，xview 是点相对相机的横坐标。点在 1，相机从 0 到 1，点的相对位置就从 1 变为 0。观察室相机只有固定俯仰，横轴关系仍成立。它解释了方向，不直接给出像素位移。
延伸：裁剪之后还有什么？
对裁剪后保留的几何进行透视除法：xndc = xclip / wclip，y、z 同理。w 是第四个坐标，不能随便丢弃。NDC 再经视口映射成为窗口坐标。在本实验 OpenGL/WebGL 约定中，NDC 的 x、y、z 范围均为 [−1, 1]；默认深度范围映射到 [0, 1]。完整投影矩阵与裁剪条件留到第 4 周。
两个着色器，各自改变什么？
顶点着色器
gl_Position = uProjection * uView
            * uModel * vec4(aPosition, 1.0);
这行就在 renderer.js。改变 uModel 的平移，会改变顶点投影后的覆盖位置；给片段换色无法修正相机姿态错误。
片段着色器
gl_FragColor = vec4(uColor * brightness, 1.0);
uColor 是基础色，brightness 是简化照明系数。改颜色通常改变外观，不移动轮廓；写入的颜色仍可能因深度测试失败而不进入最终图像。
片段 ≠ 最终像素
一个屏幕像素可能先后收到多个三角形的候选片段；被遮挡的片段可能被丢弃。也不能把一个三角形理解为只运行一次片段着色器。本周先记住“顶点决定几何位置，片段决定候选颜色”。

这周最容易混淆的四件事
  • 移动相机不是移动所有世界坐标。观察变换改变的是表达方式；物体世界位置可以保持不变。
  • 顶点着色器不负责填满整个三角形。覆盖哪些位置由光栅化决定，属性还会被插值。
  • 后画不一定在前。开启正确的深度测试后，不透明物体应由深度关系决定遮挡。
  • 渲染不会自动还原真实照片。我们选择的光照和材质模型本身也可能过于简化。
