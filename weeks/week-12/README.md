## 自主学习讲解

### 像素不是无限小的几何点

细线可能只覆盖像素的一小部分。只测中心，得到的往往是 0 或 1；稍微移动线，中心从外到内，像素就骤变。多次采样通过估计像素内的覆盖/信号平均，让结果更接近一个区域上的积分。

I_pixel ≈ (1/N) Σ f(x_i,y_i)

f 是线性光意义下的连续信号，(x_i,y_i) 是像素内采样位置，N 是样本总数。N 不是图像宽度；本实验控件 k 表示每轴 k 个子样本，因此 N=k²。

### 高频信号会伪装成低频图案

缩小棋盘时，一个像素可能跨过多个黑白格。只取少数点可能产生本不存在的大块图案或摩尔纹；时间上移动相机则表现为闪烁。增加采样、正确预过滤或适合足迹的 mipmap，都是为了控制被保留的频率，而非单纯把最终图像抹糊。

Nyquist 直觉要求采样频率足够表达保留信号，但真实图像边缘不是严格带限信号，不能背一句“每周期两个点”就断言所有锯齿解决。采样前的过滤和像素滤波核也重要。

### MSAA 和整段着色都重复执行的 SSAA 不相同

SSAA 对多个子位置完整求值后合成；MSAA 主要增加几何覆盖/深度等子采样，通常不对每个子样本都重新执行完整片段着色。具体着色频率还会受 API 与 sample shading 等设置影响。

本实验在每个子位置都求程序图案，因此更接近简单网格 SSAA，不能拿它的计算次数直接估计 MSAA 成本。它也没有 TAA 的跨帧历史、运动向量和反遮挡处理。

### 编码值不是线性光强

常见 sRGB 图像把线性分量 L 非线性编码为 C，给暗部更多数值分配。C 的中间数值不等于物理光强的中间值。因此光照、透明混合或降采样应先在线性光空间处理，再按输出约定编码。

L = C/12.92　(C ≤ 0.04045)
L = ((C+0.055)/1.055)^2.4　(其他)

编码反向为：L≤0.0031308 时 C=12.92L，否则 C=1.055L^(1/2.4)−0.055。这里 C、L 均是 [0,1] 的单个颜色分量，不是曝光或 Gamma 滑块。简单 C^2.2 只是常见近似，实验使用分段函数。

### 黑白各一半，为什么不应该输出 0.5 编码值？

黑白在线性空间为 0 和 1，等权平均得到 L=0.5，编码后约 C=0.735。直接平均 sRGB 编码则得到 C=0.5，对应线性 L≈0.214，明显更暗。若已经由 GPU 的 sRGB 纹理自动解码，又手动解一次，会产生双重转换错误。

将此联系到重建数据：输入照片的编码、损失计算空间、渲染器输出与显示流程需要一致。PSNR 等指标也应明确它测量的是哪个空间，不能只报一个没有条件的分数。

## 交互实验

同一信号：采样比较 + 颜色空间比较

上方左图每像素一个中心样本，右图每轴 k 个网格子样本。下方两条色带分别在编码值与线性光中平均。改变相位观察细边/棋盘跳变，再改变颜色权重。

可调输入：

- 右图每轴样本 k（总数 k²）（samples）：默认 4；1=1（共1），2=2（共4），4=4（共16），8=8（共64）
- 程序信号（pattern）：默认 line；line=斜向细线，checker=旋转高频棋盘
- 亚像素相位/位移（phase）：默认 0，范围 0–1
- 细线宽度（像素）（lineWidth）：默认 0.6，范围 0.2–3
- 棋盘频率（格/像素）（frequency）：默认 0.42，范围 0.1–0.9
- 颜色 B 的混合权重 t（mix）：默认 0.5，范围 0–1
- 端点 A 的 sRGB 编码值（dark）：默认 0，范围 0–1
- 端点 B 的 sRGB 编码值（bright）：默认 1，范围 0–1

### 核心代码

signal 返回线性 0/1；renderSamples 把 k² 个值按权重相加。先预测，再把 1/(k*k) 错改为 1，观察它为何不再是平均。颜色部分应 decode→混合→encode；可删除 decode 构造错误，再用黑白各半核验。

```js
const signal = (x,y)=> input.pattern === 'line'
  ? (Math.abs(y-(0.55*x+8+input.phase)) < input.lineWidth/2 ? 1 : 0)
  : ((Math.floor((0.8*x+0.6*y)*input.frequency+input.phase)
     +Math.floor((-0.6*x+0.8*y)*input.frequency))&1);
const k = Number(input.samples);
const left = renderSamples(1, signal, 1);
const right = renderSamples(k, signal, 1/(k*k));
const wrong = (1-input.mix)*input.dark+input.mix*input.bright;
const linear = (1-input.mix)*decode(input.dark)+input.mix*decode(input.bright);
return {left,right,wrong,correct:encode(linear),linear,
        width:input.width,height:input.height,k};
```

### 只读脚手架

框架先执行下列 helper，再执行核心代码；页面可展开查看，下载包含两部分。

```js
function decode(C) {
  return C <= 0.04045 ? C/12.92 : ((C+0.055)/1.055)**2.4;
}
function encode(L) {
  return L <= 0.0031308 ? 12.92*L : 1.055*L**(1/2.4)-0.055;
}
function renderSamples(k, signal, weight) {
  const image=[];
  for(let y=0;y<input.height;y++) for(let x=0;x<input.width;x++) {
    let sum=0;
    for(let j=0;j<k;j++) for(let i=0;i<k;i++)
      sum += signal(x+(i+.5)/k,y+(j+.5)/k);
    image.push(sum*weight);
  }
  return image;
}
```

采样回答“对区域怎样估计”，颜色空间回答“数值代表什么”；先分清，再平均。

## 预测、实验、解释

### 让“更多样本总是更好”变成可检验的表述

固定细线宽度，对比 k=1、2、4、8，并改变亚像素相位。预测总样本数，记录一个单样本跳变明显的例子。说明增加样本是在估计什么，而不是泛称“更清晰”。

提示：每轴 k 个点，总数为 k²。区域平均会产生部分覆盖值，不会凭空恢复所有高频细节。

### 手算一个颜色平均，然后故意做错

对黑白各半，先手算线性结果与编码结果；再用 A=0.1、B=0.9、t=0.25 重做。修改核心代码删除 decode 或重复 encode，解释错误方向，并说明截图是否可以替代校准光度计。

提示：0.5 是线性中点，但不是 sRGB 编码中应显示的中点数值；屏幕与观察环境仍有额外因素。

## 理解检查

### 1. 每轴 4 个子样本时，像素共求值多少次？

1. 4
2. 8
3. 16

<details><summary>作答后再看解析</summary>

答案：3。二维网格总数为 4×4=16，不能把每轴数量当作总数。

</details>

### 2. 黑白在线性空间各一半，正确 sRGB 编码约为？

1. 0.214
2. 0.5
3. 0.735

<details><summary>作答后再看解析</summary>

答案：3。线性平均 L=0.5，按 sRGB 编码得到约 0.735；直接编码平均 0.5 对应更暗的线性光。

</details>

### 3. MSAA 是否总对每个覆盖子样本完整运行片段着色器？

1. 总是
2. 通常不是，覆盖与着色频率需要区分
3. 完全不做覆盖测试

<details><summary>作答后再看解析</summary>

答案：2。常见 MSAA 共享片段求值并增加覆盖/深度样本；设置可能改变实际着色频率。

</details>

### 4. 先平均深色/亮色的 sRGB 编码值，主要问题是？

1. 没有几何信息
2. 编码值与线性光不是线性关系
3. 每次一定产生NaN

<details><summary>作答后再看解析</summary>

答案：2。线性组合应对应光的线性量，非线性编码需要先解码。

</details>

### 5. 棋盘缩小时出现大块伪图案，最合理解释是？

1. 网格顶点一定错误
2. 高频信号采样不足造成混叠
3. 材质必须变金属

<details><summary>作答后再看解析</summary>

答案：2。频率过高的信号可能被少量采样误表示为低频；应考虑预过滤与合适足迹。

</details>

### 6. 若纹理格式已自动解码 sRGB，又手工解码会怎样？

1. 更精确
2. 可能形成双重转换，导致数值错误
3. 一定不变

<details><summary>作答后再看解析</summary>

答案：2。必须知道输入已在哪个空间；重复解码与漏解码都是流程错误。

</details>

## 常见误区

- 平滑不等于准确；错误颜色空间也能生成很平滑的渐变。
- MSAA、SSAA、纹理过滤和TAA处理的对象及成本不同。
- 增加采样不等于增加原始几何或恢复被预先丢弃的信息。
- sRGB 分段传递函数不应一律当成精确的 2.2 次幂。
