## 自主阅读

### 从一张具体图提出问题

不要把题目写成“学习PBR”。写成可以检验的问题，例如：“相机右移后，镜面中的参照球应向哪边移动？”或“关闭可见性查询后，球底阴影为什么消失？”问题越具体，越容易设计能推翻自己的实验。

项目可以沿用本页球体场景，也可以换成第8周的中期场景。未完成光线追踪分支的学习者可使用给定求交框架，重点解释相机、光照和一个诊断过程；不要求从零重写整个渲染器。

### 把场景写成可复现的数据，而不是凭感觉调参

至少记录相机位置与FOV、物体的位置和尺寸、线性基础色、镜面混合权重、光源方向、遮挡开关及核心代码。只有截图没有条件，别人无法判断你到底改了什么。

图像 = 渲染器(场景，成像规则，数值设置)

这个函数式表达强调责任边界，不是一个可直接求导的完整物理公式。相机改变构图，几何改变命中与遮挡，材质改变响应，光源与可见性改变入射贡献。

### 一份可验证的排错记录长什么样？

先保留基线。对“球面看起来凹进去”提出候选原因：选了错误的求交根、法线方向错误、材质造成视觉误导。然后切到法线和距离调试图，再只改根选择。如果多个条件一起变好，就还不能把改善归因于某一项。

本页可故意启用远根优先。近/远根选择不是绘制顺序；简化距离图是 exp(−0.28t)，不是第6周的透视深度缓冲。请用探针数值 t 和 n 核对自己的解释。

### 改进需要说明约束，不能只展示更漂亮的结果

增大分辨率、增加样本、改灯光和改变材质都可能改善观感，但成本与物理含义不同。本页为固定160×100单样本CPU射线图，计时仅测内核。若要研究噪声与样本数，请回到第15周；若研究实时GPU性能，回到第13周真实WebGL实验。

最终说明至少包含：一张基线图、一张对照图、一段核心代码、一条定量或几何检验，以及一个仍未排除的限制。不要把本页参考场景运行成功当作自己的项目已经通过。

## 交互实验

可组合的期末小场景与故障工作台

选择相机、尺寸、材质、遮挡与调试方式；再直接修改场景和射线核心。先保存基线PNG，改变一项后保存对照；用右侧探针核对可见性。

### 修改核心计算

```js
const aspect=160/100, fov=Number(input.fov)*Math.PI/180;
function direction(u,v){ return unit([u*Math.tan(fov/2)*aspect, v*Math.tan(fov/2), -1]); }
function reflector(d,n){ return sub(d,scale(n,2*dot(d,n))); }
// 修改位置/尺寸/颜色前，先写下你希望验证的单个问题。
const scene=[
 {id:'项目主球',p:[-.25,0,-2.6],r:Number(input.radius),c:[.15,.62,.5],m:Number(input.mirror)},
 {id:'参照球',p:[.95,-.15,-3.4],r:.55,c:[.78,.2,.07],m:.08},
 {id:'地面',p:[0,-100.7,-3],r:100,c:[.72,.7,.63],m:0}
];
return renderRay({scene,origin:[Number(input.cameraX),.2,.2],direction,reflector,depth:2,
 mode:input.mode,farRoot:input.root==='far',probeX:0,shadow:input.shadow==='on'});
```

p 是世界球心，r 是半径，c 是线性基础色，m 是理想镜面与简化漫反射的混合权重，不是PBR金属性或粗糙度。主球、参照球和地面都参与真正的最近求交、遮挡与反射。修改相机方向生成式时，先核对宽高比与Y翻转。

只读脚手架在页面详情与 lesson.js 的 lab.prelude 中可查看；下载代码包括脚手架。修改在 Worker 中执行，错误或超时保留上次图像；不会自动改写磁盘文件。

### 实验边界

解析球与简化方向光CPU渲染器；镜面混合并非完整PBR。固定低分辨率、两次反射，无真实网格、GPU性能计时、路径追踪噪声、透明折射、生产级阴影或颜色管理流程。

## 理解检查

1. 最终图和基线同时改变了灯光、材质和相机，能把改善归因于某一项吗？
   A. 能，看起来更好即可
   B. 不能，需要控制变量与进一步对照
   C. 只要参数写下来就一定能

<details><summary>作答后查看解析</summary>

参考选项：B。记录是前提，但同时变化仍存在混杂因素；需要隔离变量或明确联合改动的有限结论。

</details>

2. 本页“镜面混合0.8”可以直接解释为PBR金属性0.8吗？
   A. 可以，都是0到1
   B. 不可以，参数模型不同
   C. 只要颜色相同就可以

<details><summary>作答后查看解析</summary>

参考选项：B。本页在简化漫反射与理想反射间混合，没有完整金属/介质Fresnel与微表面BRDF。

</details>

3. 阴影消失时，首先应检查哪类证据？
   A. 光源可见性查询与偏移/遮挡设置
   B. 只增大主球颜色值
   C. 把所有法线取反

<details><summary>作答后查看解析</summary>

参考选项：A。阴影是可见性问题，应先检查光源方向射线是否被遮挡；亮度变化不自动修复可见性。

</details>

4. 一张结果图加“CPU内核8ms”，足以说明实时GPU达到125FPS吗？
   A. 足够
   B. 不足，计时边界、显示、数据传输和GPU路径不同
   C. 只要8ms小于16.7ms即可

<details><summary>作答后查看解析</summary>

参考选项：B。帧率是系统呈现的结果，不能把一个CPU内核倒数直接宣称为GPU帧率。

</details>

5. 一个好的未解决限制应该是什么？
   A. 没有任何问题
   B. 明确尚未测试或尚未覆盖的条件及影响
   C. 仅写“还可以更好看”

## 常见误区

- 课程网站或预制示例可运行，不代表学习者期末项目已经完成。
- 同时调很多参数得到漂亮图，不能自动解释改进原因。
- 不同渲染模型中的0到1参数不一定具有相同物理意义。
- 一张截图不能证明数值鲁棒性或性能稳定，必须记录条件与反例。
