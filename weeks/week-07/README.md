## 概念与必要数学

### UV不是像素坐标，纹理也不是模型本身

UV把模型表面位置映射到二维图像参数。u、v在[0,1]内通常覆盖纹理的一份范围，但重复寻址允许超出这个区间。texel是纹理中的离散元素，屏幕像素是输出图像中的离散位置，两者不是一一对应。

若一个屏幕像素只跨过0.5个texel，是纹理放大；若跨过8个texel，是缩小。一次最近邻采样仍然只选一个texel，所以在缩小时很可能错过其他texel所包含的变化。

### 最近邻与双线性，都是局部重建规则

最近邻直接取最近texel的值，边界会突然跳变。双线性在纹理二维网格的四个邻居之间插值；设小数偏移为α、β：

q = (1−β)[(1−α)q₀₀ + αq₁₀]

+ β[(1−α)q₀₁ + αq₁₁]

α、β是相对相邻texel中心的位置。本实验使用x=uN−0.5的中心约定，N为该层纹理宽度。双线性能平滑放大时的块状边界，但缩小时仍只取基础层的局部四点，并不自动平均一个大足迹。

### mipmap是预先缩小的一组纹理

从64×64基础图开始，每层对2×2区域取均值，生成32×32、16×16，直到1×1。这些是实际计算出来的层，不是给最终画面套模糊滤镜。

λ ≈ log₂ ρ

q = (1−t) sample(level⌊λ⌋) + t sample(level⌊λ⌋+1)

ρ为每个屏幕像素覆盖的texel数量的线性尺度，λ是层级，t为λ的小数部分。本课足迹是等比例、无旋转的正方形，因此用一个ρ即可。每层内部再做双线性，相邻层间插值通常称三线性过滤。

越远的纹理需要舍弃无法由输出像素可靠表达的高频细节。mipmap提高稳定性不是恢复细节；如果误选过粗的层，近处也会过度模糊。

### 从“看起来闪”变成可验证的采样问题

固定纹理和缩放，只让UV有极小偏移。如果输出颜色大幅改变，可提出“采样不足、基础层过滤不匹配足迹”的假设。实验同时显示三种过滤，避免用不同图像或不同参数比较。

本课还计算一小步Δu=1/256前后采样值的平均绝对变化，作为条件性的数值对照。它不等价于人眼感知的全部闪烁指标，也不能证明某个设置对所有纹理都更好。

延伸：斜着看地面为何仍模糊？

斜面足迹通常是细长形状，单一方形mip层可能沿一轴过度模糊、另一轴仍采样不足。各向异性过滤沿主要方向增加合适的采样。本实验只做各向同性足迹，不能用它评估真实斜视纹理质量。

## 交互实验：同一张纹理，三种采样规则并排

三个输出始终使用相同UV、纹理与采样足迹。调大ρ进入缩小，再轻推UV相位；最近邻/双线性/三线性mipmap结果来自各自真实采样函数。

可调参数：

- `footprint`：每像素覆盖的texel尺度 ρ，默认 5.25。
- `offset`：UV的u偏移（重复寻址），默认 0.125。
- `frequency`：64×64棋盘的格数，默认 16。

预设对照：纹理放大：看局部插值；纹理缩小：观察闪烁；整数足迹可能掩盖/加重别名；稍改相位作反例。

### 亲手修改核心代码

核心可直接改层级选择与混合：把lod改为0会禁用mipmap选择；加1会偏向更粗层。先预测稳定性与模糊的取舍。脚手架中展示双线性和2×2均值构层，下载代码后可进一步修改。

```js
const levels=buildMips(buildTexture(input.frequency));
const lod=Math.max(0,Math.min(levels.length-1,Math.log2(input.footprint)));
const low=Math.floor(lod),high=Math.min(low+1,levels.length-1),t=lod-low;
const trilinear=(u,v)=>(1-t)*bilinear(levels[low],u,v)+t*bilinear(levels[high],u,v);
return {lod,low,high,t,levels:levels.map(tex=>({n:tex.n,data:Array.from(tex.data)})),
  panels:[image((u,v)=>nearest(levels[0],u,v)),
          image((u,v)=>bilinear(levels[0],u,v)),image(trilinear)]};
```

框架把脚手架与上面的核心函数体合并后放进 Worker 执行；返回的数据驱动画布。编辑成功代码后控件沿用新版本，错误/超时保留上次图像。可下载包含脚手架的完整核心实验代码。

### 应该观察到什么

过滤规则需要匹配屏幕足迹。最近邻与双线性并不自动解决缩小混叠；mipmap用预过滤牺牲不可表达细节，提高稳定性。

### 简化与不能推出的结论

CPU灰度标量纹理采样器，使用等比例正方形足迹与周期棋盘；mip链真实2×2均值构建。未模拟GPU导数、各向异性、透视UV插值、运动时间采样和颜色空间；不是GPU过滤质量或性能实测。

## 预测、实验、解释任务

### 把纹理坐标与屏幕采样分开说清楚

保持UV相位不变，把ρ从0.5改到8。先计算每个输出像素大约覆盖多少个基础texel面积，再解释为何基础层双线性只取四点可能不足。

需要时再看提示：正方形足迹面积约ρ²；四点局部插值不是对整个大面积的积分。

### 构造最近邻采样的反例

使用整数足迹预设，再切换小相位预设。先预测图像会保持棋盘、变成条纹还是接近单色，并说明为什么单个“看起来平滑”的相位不能证明没有混叠。

需要时再看提示：周期纹理与规则采样可以锁相，输出可能错误地稳定。

### 修改核心LOD，说明代价

把lod固定为0，再改为默认值+1并夹紧范围。比较远处稳定性和近处细节，并记录一种你不愿接受的过度模糊案例。

需要时再看提示：更粗层不是无条件更好，先说明你要表达的输出分辨率和足迹。

   - 固定一一对应
   - UV是表面参数，需经过采样映射到texel
   - UV就是GPU深度

2. 双线性过滤在单层纹理通常使用多少个邻近texel？
   - 1个
   - 4个
   - 整张纹理

3. ρ=8 texel/像素，理想各向同性LOD约为多少？
   - 3
   - 8
   - 64

4. 三线性过滤在本实验指什么？
   - 三种颜色直接相加
   - 每层双线性，再在相邻mip层间线性混合
   - 直接做三维体纹理

5. mipmap解决缩小问题的主要代价是什么？
   - 可以无损恢复所有细节
   - 存储预过滤层，并丢弃输出无法可靠表达的高频细节
   - 让所有UV变为0

   - 总能完全匹配
   - 一轴过度模糊、另一轴仍不足，需研究各向异性

## 常见误区

- 把texel和像素当成同一种离散单位：先问映射尺度。
- 认为双线性足以解决一切缩小闪烁：检查采样足迹。
- 认为越模糊越正确：过滤必须匹配目标足迹，不能抹去仍可表达的细节。
