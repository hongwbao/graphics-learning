## 概念与必要数学

### 先观察物体中心，别只盯住轮廓

想象路口上一个方向箭头：它已经被放在路口位置，旋转时应保持中心不动。如果先把箭头沿世界 X 移开，再绕世界原点旋转，箭头中心会沿圆弧运动。画面看起来都“转了”，但含义完全不同。

本周用同一局部三角形做两次变换：青色为 T·R，砖红为 R·T。虚线轨迹标出局部原点的世界位置。先预测当角度从 0° 变到 90° 时，哪个中心会移动，再运行实验。

### 固定约定，才能讨论顺序

采用右手坐标系、列向量，点写作 p=(x,y,z,1)ᵀ。矩阵乘法从右向左作用。R 是绕世界 Z 轴的旋转；T 把位置沿 X 轴移动 t 个单位。为突出顺序，实验把模型放在 z=0 的平面。

p₁ = T·R·p　（先 R，后 T）

p₂ = R·T·p　（先 T，后 R）

乘法顺序不是“读起来顺手”的书写习惯。CPU 中先调用 translate 再 rotate，也不能仅凭函数调用的先后猜结果；要看库是在左乘还是右乘。列主序描述的是数组存储顺序，不自动决定你使用列向量还是行向量。

### 把矩阵展开成可以手算的几何

R_z(θ)(x,y) = (x cosθ − y sinθ, x sinθ + y cosθ)

T(x,y) = (x+t,y)

θ 为逆时针正角，cosθ 与 sinθ 给出旋转后基向量的分量。于是 T·R 的结果在旋转后加 (t,0)；R·T 则连同平移向量一起旋转。对局部原点 p=(0,0,0,1)：前者中心始终是 (t,0)，后者中心是 (t cosθ,t sinθ)。

手算：t=2，θ=90°，p=(1,0,0,1)。T·R·p=(2,1,0,1)，R·T·p=(0,3,0,1)。中心与一个非中心顶点都要查；只看某一个特殊点可能遗漏错误。

### 矩阵的列，是变换后的基与原点

对仿射矩阵 M=[eₓ eᵧ e_z o; 0 0 0 1]，前三列描述原坐标基向量变换后的方向，最后一列是局部原点的世界位置。点的 w=1 会带入 o，方向 w=0 不会。这正好连接第 2 周的基底展开。

重建中相机 pose 的旋转和平移也不能随意交换。给定 world→camera 的 R、t 时，camera→world 需要求整个变换的逆；不能只把平移符号改掉。第 4 周会把 V 作为观察变换使用。

延伸：如何绕任意支点 c 旋转？

先把 c 移到原点，再旋转，再移回去：M=T(c)R T(−c)。对 p=c，代入即可验证支点固定。不要靠背乘积，先写动作，再按约定翻译。

## 交互实验：自转还是公转：同时对照 T·R 与 R·T

两组结果都由实际4×4矩阵乘法产生。改变角度和平移，查看中心与同一顶点坐标；可以改核心代码制造错误，并用中心轨迹解释。

可调参数：

- `angle`：绕 Z 轴角度 θ（度），默认 40。
- `tx`：沿世界 X 平移 t，默认 2。
- `size`：模型局部大小，默认 0.7。

预设对照：手算核验：90° / t=2；会掩盖错误的零旋转；会掩盖错误的零平移。

### 亲手修改核心代码

R、T 分别是旋转/平移矩阵；mul4(A,B) 返回 A·B。将 RT 改为 mul4(T,R) 后，两种图形会重合；先预测再改。修改局部顶点时，w=1 的点编码不要丢掉。

```js
const R = rotateZ4(input.angle * Math.PI / 180);
const T = translate4(input.tx, 0, 0);
const TR = mul4(T, R); // 列向量：先旋转，再平移
const RT = mul4(R, T); // 列向量：先平移，再旋转
const local = [[-.55,-.35,0,1],[.75,0,0,1],[-.55,.35,0,1]]
  .map(p => [p[0]*input.size,p[1]*input.size,0,1]);
return {tr:local.map(p=>transform4(TR,p)),rt:local.map(p=>transform4(RT,p)),
  centerTR:transform4(TR,[0,0,0,1]),centerRT:transform4(RT,[0,0,0,1]), TR,RT};
```

框架把脚手架与上面的核心函数体合并后放进 Worker 执行；返回的数据驱动画布。编辑成功代码后控件沿用新版本，错误/超时保留上次图像。可下载包含脚手架的完整核心实验代码。

### 应该观察到什么

验证顺序时选非零角度、非零平移与至少两个顶点；中心的轨迹直接揭示平移是否被旋转。

### 简化与不能推出的结论

用CPU对4×4齐次矩阵做真实乘法，再作二维正交绘图；不是GPU帧捕获。仅绕Z旋转、沿X平移，不处理层级场景或透视。

## 理解检查

1. 列向量约定下，T·R·p 的动作顺序是什么？
   - 先T后R
   - 先R后T
   - 两者始终相同

2. t=2，θ=90°，局部原点经R·T后在哪里？
   - (2,0)
   - (0,2)
   - (0,0)

3. 只在θ=0°时比较TR与RT一致，能否证明实现正确？
   - 可以
   - 不可以，此时R是单位矩阵
   - 只要画面没有报错就可以

4. “列主序数组”是否足以说明使用了列向量数学约定？

## 常见误区

- 把函数调用先后等同于几何作用顺序：先查左乘/右乘约定。
- 把存储布局和向量表示混为一谈：分别声明列主序与列向量。
- 只比较零角度或模型中心：用一般参数和多个点验证。
