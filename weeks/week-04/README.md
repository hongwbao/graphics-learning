## 概念与必要数学

### 先把“从哪里看”和“怎样成像”拆开

世界中点的位置不依赖相机，但它相对相机的坐标依赖相机。观察变换V负责把世界坐标表达成相机坐标；投影P才决定近大远小或平行投影。实验相机只平移，朝向固定为−Z，+Y向上，没有偷偷重新看向原点。

p_view = V p_world

p_clip = P p_view

重建外参常表示world→camera，这与V的映射方向相近，但仍需核对轴约定、手性和矩阵布局。仅凭变量名叫pose不能判断可直接使用，camera→world位姿需要取逆。

### 透视关系来自相似三角形

设相机向−Z看，一个前方点的观察坐标z_view<0。令d=−z_view>0为前向距离，竖直视场角为φ，f=1/tan(φ/2)。当宽高比为a时：

x_ndc = (f/a) x_view / d

y_ndc = f y_view / d

同样的物体距离加倍，投影大小约减半。增大φ会减小f，视野变宽，固定位置的物体变小。FOV变化不会改变物体间的透视距离比；移动相机会改变各物体的距离比，所以“后退”和“放大视野”通常不等价。

### 为什么先输出四维坐标？

透视矩阵令w_clip=−z_view，将除法推迟。顶点着色器写出的gl_Position是(x_clip,y_clip,z_clip,w_clip)，不是像素位置。GPU先按齐次条件裁剪几何，再除以w得到NDC。

−w_clip ≤ x_clip,y_clip,z_clip ≤ w_clip

p_ndc = (x_clip,y_clip,z_clip) / w_clip

本课使用OpenGL/WebGL约定，NDC三个轴都在[−1,1]。跨过裁剪面的线段会产生新端点，不是简单地“只要任一顶点在外面就扔掉整个物体”。本实验确实在四维空间切线段，再做除法。

### 正交投影与视口，各自做什么？

正交投影保留平行关系，屏幕尺寸不随深度改变。它适合技术视图或某些地图，但同样需要观察变换、裁剪和深度测试。本课正交模式固定竖直范围[−3,3]，因此FOV滑块只影响透视模式。

x_pixel = (x_ndc + 1) W/2

y_window = (y_ndc + 1) H/2

W、H为视口宽高。这是OpenGL窗口坐标的左下原点写法；Canvas绘图以左上为原点，所以本图显式翻转Y。若把两种坐标混用，画面可能上下翻转。视口映射不负责产生近大远小。

延伸：FOV与相机内参怎样联系？

在对称针孔模型且主点位于图像中心时，f_y(pixel)=H/[2 tan(φ/2)]。一般重建相机的主点、非对称视锥、图像缩放与畸变还需单独处理；本实验没有镜头畸变。

## 交互实验：双视图：观察空间与真正裁剪后的投影

左侧把观察空间的前向距离画成剖面，右侧显示经四维裁剪后的线框。两个立方体边长相同，后一个更远。比较投影方式、距离、FOV和近远面。

可调参数：

- `mode`：投影方式，默认 perspective。
- `distance`：相机Z位置，默认 5。
- `cameraX`：相机X位置（朝向固定），默认 0。
- `fov`：竖直FOV（度，仅透视），默认 50。
- `near`：近裁剪面 n，默认 0.5。
- `far`：远裁剪面 f，默认 15。

预设对照：比较近大远小；近面切入模型；正交：改变距离不改大小。

### 亲手修改核心代码

V只做相机平移的逆；P负责投影。clipSegment对六个齐次平面切线段。将最后的x/p[3]改为x，观察忘记透视除法时结果如何失真；只对可见线段做除法，避免相机后方点的数值误用。

```js
const n=input.near, f=input.far;
const P=input.mode==='perspective'
  ? perspective4(input.fov*Math.PI/180,1,n,f)
  : [1/3,0,0,0, 0,1/3,0,0, 0,0,-2/(f-n),0, 0,0,-(f+n)/(f-n),1];
const V=translate4(-input.cameraX,0,-input.distance);
const cubes=[[-1.3,0,0],[1.3,0,-3]].map(center=>{
  const view=corners.map(p=>transform4(V,[p[0]*.7+center[0],p[1]*.7,p[2]*.7+center[2],1]));
  const clip=view.map(p=>transform4(P,p));
  const segments=edges.map(([i,j])=>clipSegment(clip[i],clip[j])).filter(Boolean)
    .map(pair=>pair.map(p=>p.slice(0,3).map(x=>x/p[3])));
  return {view,segments,sample:clip[6]};
});
return {cubes};
```

框架把脚手架与上面的核心函数体合并后放进 Worker 执行；返回的数据驱动画布。编辑成功代码后控件沿用新版本，错误/超时保留上次图像。可下载包含脚手架的完整核心实验代码。

## 理解检查

1. 观察变换V主要做什么？
   - 决定材质颜色
   - 把世界位置表达为相机坐标
   - 直接把三角形变成像素

2. 相机向−Z看，前方点通常满足什么？
   - z_view<0，透视w=−z_view>0
   - z_view>0且w必为1
   - z_view永远等于深度缓冲值

3. FOV增大而其他条件固定，物体通常怎样？
   - 变大
   - 变小，视野变宽
   - 位置与大小完全不变

4. 裁剪与透视除法的概念顺序是？
   - 先除以w，再按像素裁剪
   - 先在齐次空间裁剪，再除以w
   - 两者可任意交换且不需前提

5. 正交模式里相机后退，未触发裁剪时模型尺寸怎样？
   - 一定减半
   - 保持不变
   - 随深度二次增长

6. OpenGL/WebGL默认约定下的NDC深度范围是？
   - [0,1]
   - [−1,1]
   - 任意正实数

## 常见误区

- 把后退相机等同于改变FOV：多深度物体的相对尺度可区分两者。
- 把gl_Position直接当屏幕像素：中间还有裁剪、除w与视口。
- 以为near只是画面上的一条线：它会切除几何，且影响下一周讨论的深度精度。
