## 自主学习讲解

### 第一遍：不是拍颜色，而是记下最近的表面

将光源当作相机。对每个光源纹理格子，保存从灯方向看最近的深度 D(u,v)。这张图不需要最终材质颜色；它回答的是“灯在该方向上先遇到了谁”。本实验用方向光与正交投影，所以深度是沿光源视向的线性坐标。

左图由地面与盒子的真实三角形投影、覆盖和深度测试生成。没有用一张预制阴影图片替代 shadow map。灰度只便于显示深度，黑色区域不等同于主视图中的阴影。

### 第二遍：把当前点也放进灯的坐标系

shadow = [d_current − bias > D(u,v)]

将当前世界点投到同一个光源投影下，取其纹理坐标与深度。若它比纹理记录的最近深度更远，就有别的表面挡在前面。d_current、D 和 bias 必须使用相同深度约定；比较符号不能脱离约定记忆。

本实验 q=−p·l，l 指向光源来向，因此较小 q 表示更靠近灯。正 bias 从当前 q 中减去，等价于在比较时把接收点稍微移近灯，减少自遮挡；它不真的移动几何。

### 为什么会长出条纹，又为什么阴影会悬空？

shadow map 只有有限分辨率与精度。同一倾斜平面上，主视图点与最近纹素中心并不相同；存储/采样偏差可能把表面误判成在自己后面，产生 shadow acne。较大的 bias 能减少误判，但也会吞掉真实的近接触遮挡，让阴影脱离物体（常称 peter-panning）。

改变纹理分辨率、光源覆盖范围、深度精度和表面斜率，都会改变所需偏移。一个对本场景有效的常数，不是所有场景的通用参数。

### 过滤比较结果，别把深度平均误认成软阴影真值

最简单的 PCF 在邻近多个纹素上分别做深度比较，再平均“可见/遮挡”的 0/1。它可以让阶梯边界更平滑，但没有模拟有限面积光源，也没有恢复低分辨率里丢失的几何细节。

visibility ≈ (1/K) Σ [d_current − bias ≤ D(u_i,v_i)]

K 是实际比较次数。把深度数值先平均再比较，一般不是同一运算。实验用方形核且对边界外视为可见，这些都属于需要说明的实现约定。

## 交互实验

真实 shadow map：左看深度，右看比较

调低分辨率、令 bias=0，再改变地面斜率。随后逐渐增大 bias，并比较不开滤波与 3×3 PCF。右图为主视图的俯视地面与盒子顶面，可直接观察阴影范围。

可调输入：

- Shadow map 边长（resolution）：默认 32，范围 8–96
- 深度偏移（光源坐标单位）（bias）：默认 0.15，范围 0–1.2
- 深度量化位数（bits）：默认 12，范围 4–16
- 方向光方位（light）：默认 35，范围 -180–180
- 地面 y = slope × x（slope）：默认 0.12，范围 -0.3–0.3
- 盒子高度（height）：默认 1.1，范围 0.3–1.8
- 可见性过滤（pcf）：默认 0；0=单次比较，1=3×3 PCF

### 核心代码

真正控制阴影的是 p.depth − input.bias 与 stored 的比较。先改偏移符号，再预测 acne 或脱离哪一种会增加。PCF 平均的是逐次比较结果，不是 input.map 中的深度。地图生成在只读框架中，核心函数只做第二遍可见性判断。

```js
const radius = Number(input.pcf);
const visibility = input.receivers.map(p=> {
  let lit = 0, count = 0;
  for (let dy=-radius; dy<=radius; dy++) {
    for (let dx=-radius; dx<=radius; dx++) {
      const x=p.x+dx, y=p.y+dy;
      const stored = x<0 || y<0 || x>=input.resolution || y>=input.resolution
        ? Infinity : input.map[y*input.resolution+x];
      lit += p.depth - input.bias <= stored ? 1 : 0;
      count++;
    }
  }
  return lit/count;
});
return {visibility,shadowFraction:visibility.reduce((a,v)=>a+1-v,0)/visibility.length};
```

### 如何判断结果

阴影是光源视角下的可见性比较；采样、精度、偏移、滤波各有不同作用。

### 简化与边界

CPU 两遍软件三角形光栅化；正交方向光、盒子与倾斜平面、有限量化深度。主图俯视，不处理透视光源、级联阴影、真实半影、完整边界规则或 GPU 纹理采样硬件。

## 常见误区

- 深度图灰度不是阴影强度；它表达光源深度。
- bias 的符号与数值必须对应深度约定，不能机械复制。
- PCF 不等于面积光源的物理半影，也不会恢复丢失的几何细节。
